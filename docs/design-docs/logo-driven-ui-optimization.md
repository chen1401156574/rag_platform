# 基于公司 Logo 的 UI 优化整体方向

本文档基于仓库根目录 `image.png` 的公司 Logo 制定项目 UI 升级方向。它属于长期稳定的品牌视觉与交互约束，用于指导后续前端主题、组件、页面和运营界面的统一改造。

## 1. Logo 视觉分析

### 1.1 基础构成

Logo 为横向组合标识，整体由三部分组成：

- 左侧图形：能源花瓣式放射图形，绿色叶片围绕黄色核心展开，顶部有小号字母标记。
- 中部符号：橙红色与蓝绿色的倾斜短线，形成充电、电流、速度感的视觉暗示。
- 右侧字标：`小桔充电` 深灰蓝中文字标，字形厚重、圆润、现代，强调可信赖的企业服务感。

### 1.2 色彩体系

根据视觉观察与像素抽样，Logo 的主要色彩可归纳为以下几组：

| 色彩角色 | 建议色值 | 来源与含义 | UI 使用定位 |
| --- | --- | --- | --- |
| 能源绿 | `#008E40` | 左侧叶片主色，代表清洁能源、增长、可靠运行 | 品牌主识别、图标高亮、成功状态、轻量强调 |
| 深能源绿 | `#007A36` | 从主绿下沉得到的可访问动作色 | 主按钮、选中态、焦点态、小字号白字承载 |
| 叶片浅绿 | `#6DB12B` | 左侧叶片辅助绿，带有生态与活力 | 辅助图形、浅色标签、图表第二序列 |
| 阳光黄 | `#EEC906` | 图形中心亮色，代表能量、启动、提醒 | 轻提示、等待态、低风险警示、数据亮点 |
| 充电橙 | `#EA5519` | 中部倾斜符号主色，代表充电、行动、效率 | 关键操作、发送、执行、强提醒 |
| 深充电橙 | `#C94714` | 从橙色下沉得到的可访问动作色 | 小字号白字按钮、危险前置提醒、强 CTA |
| 电流青 | `#10B0B0` | 中部蓝绿色倾斜符号，代表科技、连接、链路 | 信息状态、Trace 链路、进度、链接辅助 |
| 字标墨蓝 | `#313654` | 右侧文字主色，代表专业、稳定、企业级 | 一级文字、导航文字、管理端深色面 |

Logo 的透明底与高饱和点缀色适合承载在白色或浅色界面上，形成清爽的科技能源品牌印象。UI 不应大面积铺满高饱和色，而应采用白色、浅灰、浅绿灰作为主要界面空间，让绿色与橙色承担明确的信息和操作角色。

### 1.3 字体风格

Logo 字标呈现现代无衬线、略圆角、较高字重的中文企业字形。对应到产品 UI，应选择清晰、稳定、屏幕可读性强的系统字体组合：

- 中文优先：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`。
- 英文与数字：`Inter`、`DIN` 风格数字或系统 sans。
- 代码与 Trace ID：`JetBrains Mono`、`SFMono-Regular`、`Consolas`。
- 字重策略：标题以 600 为主，不使用过度粗黑；正文 400，重点信息 500。

### 1.4 品牌调性

Logo 传递的品牌气质可以概括为：

- 清洁能源感：绿色、叶片、阳光核心，适合轻盈、明亮、低噪声界面。
- 高效充电感：橙色斜线具有速度和行动暗示，适合用于关键操作和即时反馈。
- 企业可信感：深灰蓝字标稳定克制，适合知识管理、可追溯、运营排障场景。
- 科技连接感：蓝绿色斜线可延展为链路、节点、进度、智能推荐的视觉线索。

整体方向应是“明亮、专业、清洁、可追溯”，避免过度赛博、过度渐变和营销式大图堆叠。

### 1.5 Logo 使用边界

- 产品界面只使用仓库内真实 Logo 或由设计资产库提供的正式版本，不临摹、不重绘、不改变比例。
- 横向 Logo 在导航区建议保持 28 到 36px 高度；窄侧边栏、favicon 或移动端可使用经过确认的图形简化版。
- Logo 四周至少保留图形高度 0.5 倍的净空，避免贴边、压缩到文字不可读，或叠放在复杂背景上。
- 深色侧边栏中优先使用白色容器或正式深色版本承载 Logo；没有正式反白版本时，不直接对原图反相或重新上色。
- 对外产品文案和 UI 文案不引用第三方品牌作类比，内部设计讨论可描述为“能源花瓣”“充电斜线”等自有视觉语言。

## 2. UI 升级总原则

### 2.1 视觉关键词

- 明亮：以白色和浅绿灰作为主舞台，减少深色压迫感。
- 专业：管理端保持高信息密度、明确层级、强可扫描性。
- 清洁：减少装饰性渐变、发光和大面积色块，让功能状态成为视觉重点。
- 高效：用橙色表达“立即执行”，用绿色表达“已连接、可运行、可信”。
- 可追溯：Trace、引用、知识库等链路信息使用稳定的线性结构和清晰节点状态。

### 2.2 使用比例

建议全局色彩比例：

- 70% 中性色与白色：页面背景、卡片、表格、文本主体。
- 18% 品牌绿色：主导航选中、主按钮、状态、品牌识别。
- 7% 充电橙：发送、执行、上传确认、强提醒等关键动作。
- 3% 电流青：链路、进度、信息提示、技术状态。
- 2% 阳光黄：等待、警示、数据亮点。

禁止把橙色、黄色、青色同时大面积用于同一区域。一个页面主任务只保留一个强强调色，其他颜色退到标签、图标、细线或浅底。

### 3.2 语义 Token 与迁移映射

品牌 Token 必须先在主题入口统一，再由组件和页面消费。兼容期可以保留旧变量名，但旧变量应映射到新语义，不再继续扩散蓝紫、靛蓝或随机硬编码色。

| 当前入口 | 迁移目标 | 使用说明 |
| --- | --- | --- |
| Ant Design `colorPrimary` | `--brand-green-700` / `#007A36` | 主按钮、选中态、表单焦点和 AntD 链接默认色。 |
| Ant Design `colorInfo` | `--brand-cyan-700` | 技术信息、链路提示、运行中状态，不替代成功色。 |
| Tailwind `--primary` | `--brand-green-700` | `Button`、`Switch`、`Slider` 等基础组件默认主色。 |
| Tailwind `--ring` | `rgba(0, 122, 54, 0.24)` | 所有键盘焦点环，保持 2px 以上可见轮廓。 |
| Tailwind `--chat-user` | `--brand-green-050` | 用户消息气泡浅底，正文仍使用墨蓝或中性深色。 |
| `admin.css --accent-primary` / `--primary-color` | `--brand-green-700` | 旧变量只做兼容映射，不再代表蓝色强调。 |
| `.admin-primary-gradient` | 实心 `--brand-green-700` 或单向轻量绿 | 默认不要继续使用紫蓝渐变；高意图动作另用 `--brand-orange-700`。 |
| 图表 `primary` tone | `--brand-green-600` | 主趋势线和主序列；异常仍用语义红。 |
| 页面级 SCSS 硬编码蓝紫色 | 语义 token | 按“动作、信息、状态、文本、边框”归类替换，避免逐个颜色猜测。 |

### 3.3 全场景映射

| 场景 | 标准 |
| --- | --- |
| 全局主背景 | 使用 `#F6F8F7` 或 `#FBFCFB`，带轻微绿灰倾向，替代纯蓝背景与大面积紫蓝背景。 |
| 页面内容面 | 使用白色 `#FFFFFF`，边框 `#DFE5E2`，阴影保持极轻，避免重投影。 |
| 主按钮 | 使用 `#007A36`，悬停 `#006F31`，按下 `#005C29`，白字。 |
| 高意图操作 | 发送、立即入库、重新解析、运行测试等使用 `#C94714`，普通页面内只出现一个橙色主 CTA。 |
| 链接与信息 | 链接默认使用深绿；技术链路可用深电流青 `#0F7A82`，避免在白底使用亮青承载正文。 |
| 正文文字 | 一级文字 `#252A42`，二级文字 `#46506A`，辅助文字优先 `#5F6964`，弱辅助可用 `#6F7B75` 但不承载关键信息。 |
| 分割线与边框 | 默认 `#DFE5E2`，弱分割 `#EEF2F0`，焦点边框 `#007A36`。 |
| 成功状态 | 深能源绿文字或图标，浅底 `#EDF8F1`；小字号文本优先 `#006F31`。 |
| 运行中状态 | 深电流青文字或图标，浅底 `#DFF7F9`；小字号文本优先 `#0F7A82`。 |
| 等待或注意 | 阳光黄搭配深墨蓝文字，浅底 `#FFF6CC`。 |
| 错误状态 | 保留语义红，建议 `#D92D20`，不要用品牌橙替代真正错误。 |

### 3.4 可访问性约束

- Logo 原始明亮绿 `#008E40` 和橙 `#EA5519` 适合做品牌识别，不直接承载小字号白字。
- 小字号白字按钮使用 `#007A36`、`#C94714` 等下沉色。
- 黄色只做浅底提示，不承载白字；黄色底上的文字使用深墨蓝。
- 焦点环使用 `rgba(0, 122, 54, 0.24)`，同时保留 2px 以上可见轮廓。
- 图表中同色系相邻数据必须增加形状、线型或标签差异，不能只依赖颜色。
- 普通文字与按钮文字按 WCAG AA 4.5:1 校验，大字号标题和大型图标至少 3:1；状态色不能只靠颜色表达，必须配合文案、图标或形状。

关键组合参考：

| 组合 | 对比度参考 | 结论 |
| --- | --- | --- |
| `#008E40` 与白色 | 约 4.25:1 | 可用于 Logo、图标、大字号强调，不用于普通小字白字按钮。 |
| `#007A36` 与白色 | 约 5.47:1 | 可用于主按钮和普通字号白字。 |
| `#EA5519` 与白色 | 约 3.61:1 | 可用于图标和大字号强调，不用于普通小字白字按钮。 |
| `#C94714` 与白色 | 约 4.78:1 | 可用于橙色高意图 CTA 白字。 |
| `#10B0B0` 与白色 | 约 2.67:1 | 仅作图形、进度和浅强调；正文或链接需使用 `#0F7A82` 或更深青色。 |
| `#EEC906` 与白色 | 约 1.62:1 | 只作浅提示底或数据亮点，不承载白字。 |
| `#6F7B75` 与白色 | 约 4.41:1 | 边界值，关键辅助信息改用 `#5F6964`。 |

## 4. 布局框架

### 4.1 总体空间策略

Logo 的“放射能源花瓣”适合转译为清晰、中心明确的模块层级；“充电斜线”适合转译为快速、直接、少绕路的操作流。页面布局应保持克制、明亮、低装饰，同时让关键路径一眼可见。

布局标准：

- 使用 4px 基准网格，常用间距为 8、12、16、24、32。
- 页面左右安全边距桌面端 24 到 32px，移动端 16px。
- 管理端内容最大宽度可放宽到 1600px，列表和 Trace 页面允许全宽工作台布局。
- 用户端 Chat 主阅读区建议 760 到 920px，引用抽屉或来源面板使用右侧辅助区。
- 卡片、表格、筛选栏之间保持 16px 模块间距，复杂页面使用 24px 分区间距。
- 固定顶部栏、侧边栏、底部输入区必须为内容区预留空间，避免滚动内容被遮挡。

### 4.2 用户端布局

用户端服务连续问答，应围绕“问题输入、回答阅读、引用核验、追问补充”组织：

- 左侧或顶部保留会话与知识库上下文，不做过重导航。
- 主聊天区固定在可滚动容器内，输入区固定在底部，避免全局滚动影响输入。
- 用户消息使用浅绿底或深绿小面积头像标识，助手消息使用白底，引用徽章使用品牌绿边框。
- 临时文档解析、文件上传、推荐问题应作为输入区附近的轻量操作，不打断阅读主线。
- 引用来源以右侧抽屉、底部面板或内联可展开块呈现，优先展示文档名、页码、Chunk 摘要和相似度。

### 4.3 管理端布局

管理端服务运营与排障，应保持高密度工作台风格：

- 采用左侧导航 + 顶部工具条 + 主工作区结构。
- 侧边栏底色可使用品牌墨蓝 `#252A42` 或 `#313654`，活跃指示用能源绿，避免继续使用蓝紫渐变作为主品牌。
- 页面头部包含标题、说明、关键动作和全局搜索，说明文字不超过两行。
- 筛选栏贴近表格，复杂筛选可折叠，常用筛选始终可见。
- 表格优先支持固定表头、分页、批量操作、状态筛选、详情下钻和关键 ID 复制。
- Dashboard 使用浅底卡片与清晰指标，不做营销式大 Hero。

### 4.4 信息层级

| 层级 | 用法 | 视觉标准 |
| --- | --- | --- |
| L1 页面目标 | 页面标题、当前模块核心指标 | 20 到 24px，600，墨蓝 |
| L2 模块标题 | 卡片标题、表格区标题、表单区标题 | 15 到 18px，600 |
| L3 字段与标签 | 表单 label、表头、状态说明 | 12 到 14px，500 |
| 正文 | 回答内容、描述、表格主体 | 14 到 15px，400 |
| 辅助信息 | 时间、ID、次要说明 | 12 到 13px，使用中性文字 |
| 代码数据 | Trace ID、JSON、Prompt 变量 | 等宽字体，12 到 13px |

### 4.5 响应式与触控规则

| 断点 | 布局策略 | 关键约束 |
| --- | --- | --- |
| 375 到 767px | 单列优先，Chat 输入区固定底部，管理端筛选折叠为面板 | 页面不出现全局横向滚动；表格可使用内部横向滚动并固定首列或操作列。 |
| 768 到 1023px | 平板两栏，管理端侧边栏可收起，详情页优先上下分区 | 顶部操作区允许换行，但主操作始终靠近标题或列表。 |
| 1024 到 1439px | 标准工作台：侧边栏 + 顶部工具栏 + 主工作区 | 表格、筛选和详情下钻保持同屏可见，避免过多弹窗跳转。 |
| 1440px 以上 | 宽屏工作台，Dashboard、Trace、列表页可接近 1600px | 控制正文行长；长表格和瀑布图优先扩展数据区域，不放大装饰。 |

触控与键盘：

- 桌面紧凑按钮可以使用 32px 高度，但触屏和移动端可点击区域必须不小于 44px。
- 图标按钮视觉尺寸可为 16 到 20px，但点击热区桌面不小于 32px，触屏不小于 44px，并提供 `aria-label` 或 tooltip。
- 所有 hover 才显示的关键操作必须有键盘和触屏替代入口，不能只依赖鼠标悬停。
- 页面缩放、系统字号放大或浏览器 125% 缩放下，按钮文字、表格操作和状态徽章不能互相遮挡。

## 5. 组件设计方向

### 5.1 按钮

按钮表达操作优先级，不使用颜色堆叠制造噪声：

- Primary：深能源绿，用于保存、确认、新建、主查询。
- CTA Orange：深充电橙，用于发送消息、立即执行、开始入库、重新解析等高意图动作。
- Secondary：白底、绿灰边框、墨蓝文字，用于取消、返回、普通筛选。
- Ghost：透明底，用于表格行内动作、图标按钮、弱操作。
- Danger：语义红，只用于删除、禁用、不可逆操作。

落地标准：

- 高度：紧凑 32px，默认 36px，强调 40px。
- 圆角：6 到 8px。
- 图标：优先使用 lucide 图标，图标与文字间距 6 到 8px。
- 一个操作区域最多一个 Primary 或 Orange CTA。
- 移动端或触屏场景下，按钮点击热区不小于 44px；紧凑按钮仅用于桌面表格、工具栏和低频弱操作。

### 5.2 卡片与容器

卡片承载明确的信息组，不作为页面装饰：

- 圆角以 8px 为主，弹窗可使用 12px。
- 边框使用 `#DFE5E2`，阴影仅用于浮层和悬浮状态。
- 卡片头部包含标题、描述和动作区，内容区避免再嵌套大卡片。
- KPI 卡片左侧可使用浅绿或浅青图标底，数值使用墨蓝。
- Trace 和日志类卡片优先使用线性分组，减少花哨背景。

### 5.3 导航栏

导航应体现品牌稳定感：

- 顶部或侧边品牌区使用真实 Logo，留白充足，不压缩变形。
- 管理端侧边栏使用墨蓝底时，当前项使用绿色左侧指示条和半透明浅绿底。
- 用户端导航使用白底或浅绿灰底，当前知识库或会话状态用绿色小点表达。
- 避免将导航做成紫蓝渐变或过度发光样式。
- 折叠侧边栏时保留可识别的图形标识和当前模块高亮，展开后恢复完整 Logo 与产品名。
- 深色侧边栏中的文字、图标和 active 背景都要独立验算对比度，不能只依赖“看起来更亮”的半透明色。

### 5.4 输入框与表单

输入体验应安静、清楚、可纠错：

- 默认白底，边框 `#DFE5E2`，hover 边框 `#C8D1CC`。
- 聚焦边框 `#007A36`，焦点环 `rgba(0, 122, 54, 0.18)`。
- 错误边框使用语义红，错误文案放在字段下方。
- Textarea 与 Chat 输入区支持自适应高度，但必须设置最大高度并内部滚动。
- 必填、可选、默认值、当前生效值要在管理配置表单中明确展示。

### 5.5 表格与数据列表

表格是管理端核心组件：

- 表头使用浅绿灰 `#F6F8F7`，文字 12px、600。
- 行高默认 48px，复杂信息行可到 56px。
- hover 使用 `#EDF8F1` 的低透明版本，选中行使用浅绿底和左侧绿色线。
- 状态列使用颜色点 + 文案，不只使用颜色。
- 行内操作默认 ghost，危险操作悬停后才显红。
- ID、时间、耗时、Token 等数字使用等宽或 tabular 数字。

### 5.6 标签、徽章与状态

状态色与品牌语义绑定：

- `success`：能源绿，表示完成、可用、命中、已连接。
- `running`：电流青，表示运行中、链路、流式生成。
- `pending`：阳光黄浅底，表示等待、排队、需关注。
- `failed`：语义红，表示失败、错误、不可用。
- `disabled`：中性灰，表示停用、无权限、未配置。
- 引用徽章：浅绿底、绿色边框、墨蓝文字，hover 后边框加深。

### 5.7 图标与插画

- 基础图标统一线性风格，线宽 1.75 到 2px。
- 图标主色默认中性灰，活跃态使用能源绿，链路态使用电流青，行动态使用橙。
- 空态插画使用简单线面结合，不使用复杂 3D 或大面积渐变。
- 可以从 Logo 的倾斜短线提炼为“充电斜线”辅助符号，用于进度、发送、执行反馈，但不重复堆叠。

### 5.8 图表与可视化

图表色序建议：

1. 能源绿 `#008E40`
2. 电流青 `#10B0B0`
3. 叶片绿 `#6DB12B`
4. 充电橙 `#EA5519`
5. 阳光黄 `#EEC906`
6. 墨蓝 `#313654`

图表背景保持白色，网格线使用弱绿灰。高风险或错误数据仍使用语义红，不使用品牌橙混淆风险等级。

图表可用性要求：

- 绿色、浅绿、青色相邻时必须通过线型、点型、标签或直接标注区分，不能只靠色相差异。
- 折线图和柱状图必须提供图例、单位、时间粒度说明；时间序列需明确日、周、月或小时。
- 交互图表的 tooltip 不能只依赖 hover，至少支持键盘聚焦或点击查看。
- 数据为空、加载失败、权限不足时显示明确空态或错误态，并提供刷新、调整筛选或查看 Trace 的下一步动作。
- 数据密集页面优先提供表格替代或导出能力，图表本身应附带屏幕阅读摘要或等价说明。

## 6. 关键页面升级方向

### 6.1 登录页

- 首屏突出 Logo 与产品名称，背景使用浅绿灰或白色，不使用重渐变。
- 登录卡片保持窄宽度、清晰表单和安全提示。
- 主登录按钮使用深能源绿，辅助入口使用文字按钮。
- 如果需要背景图形，可使用低透明度花瓣放射或充电斜线纹理，但必须弱化到不干扰表单。

### 6.2 Chat 问答页

- 主体使用白色阅读面与浅绿灰背景，减少蓝紫阴影。
- 发送按钮使用深充电橙，表示“启动一次智能问答”。
- 引用徽章、选中文档、知识库上下文使用品牌绿。
- 流式生成状态可使用电流青点状节奏或细进度线。
- 推荐问题使用浅绿底标签，hover 后变为绿边框。

### 6.3 知识库与文档页

- 上传区使用绿色虚线边框，拖拽态加浅绿底。
- 入库、解析、启用等正向动作使用主绿；重新解析等强动作可使用橙色。
- 文档状态用状态点 + 文案：已完成绿、解析中青、排队黄、失败红。
- 文件类型图标保留语义色，但整体饱和度降低，避免和品牌色争夺主视觉。

### 6.4 管理驾驶舱

- KPI 卡片采用白底、浅边框、绿色或青色图标底。
- 主趋势线优先用能源绿，耗时与链路指标使用电流青，异常指标使用红。
- 页面不使用大面积 Hero 卡片，保留工作台密度。
- 指标说明、更新时间、筛选范围用中性小字，确保运营人员快速扫描。

### 6.5 Trace 可观测页面

- Trace 节点用线性时间轴或瀑布图表达，成功绿、运行中青、等待黄、失败红。
- 节点 hover 显示输入输出摘要，点击进入详情。
- Prompt、LLM 输出、检索 Chunk 使用白底代码块，边框弱绿灰。
- 关键 ID 复制按钮使用 ghost 样式，复制成功反馈用绿色 toast。

### 6.6 系统配置与意图树

- 配置项按“当前生效值、默认值、覆盖来源、修改动作”组织。
- 意图树节点使用浅绿线条和墨蓝文字，选中节点用绿色边框。
- 高风险修改使用橙色预警区，真正删除仍用红色确认。
- 保存按钮主绿，测试运行按钮可使用橙色。

## 7. 交互体验规范

### 7.1 动效原则

动效应表达“轻、快、稳”，不要制造强烈弹跳和炫光。

- 常规 hover、focus：150ms 到 180ms。
- 页面模块进入：180ms 到 240ms，透明度 + 4 到 8px 位移。
- 抽屉、弹窗：200ms 到 260ms，遮罩淡入，面板滑入。
- 流式回答、进度、运行中：使用电流青或绿色的轻量脉冲，不使用大面积闪烁。
- 尊重 `prefers-reduced-motion`，关闭非必要位移动画。

动效 Token 建议：

```css
:root {
  --motion-fast: 150ms;
  --motion-base: 200ms;
  --motion-panel: 240ms;
  --motion-ease-out: cubic-bezier(0.16, 1, 0.3, 1);
  --motion-ease-in: cubic-bezier(0.7, 0, 0.84, 0);
}
```

实现约束：

- 优先动画 `opacity` 和 `transform`，避免动画 `width`、`height`、`top`、`left` 造成重排。
- 常驻的 glow、float、blink 只能用于明确的运行中状态，不作为页面装饰背景。
- 列表进入动画最多对首屏关键项使用短 stagger，间隔不超过 40ms，避免拖慢工作台感受。
- `prefers-reduced-motion: reduce` 下保留必要状态变化，但去掉位移、闪烁、脉冲和循环动画。

### 7.2 状态反馈

- 点击后 100ms 内必须有视觉反馈：按钮 loading、进度条、toast 或行内状态。
- 长任务使用分阶段状态：排队、解析、入库、完成、失败。
- 成功反馈使用绿色 toast，文案短促明确。
- 运行中反馈使用青色 loading 或进度条，避免和成功状态混淆。
- 需要用户注意但不阻断的提示使用黄色浅底；阻断式错误使用红色。

### 7.3 操作提示

- 重要操作按钮使用图标 + 文案，表格行内弱操作可使用图标按钮并提供 tooltip。
- 删除、禁用、重新入库等高风险操作必须二次确认。
- 复制成功、保存成功、上传完成等反馈显示 2 到 3 秒。
- 错误提示要包含下一步行动，例如“重试”“查看 Trace”“检查配置”。

### 7.4 微交互符号

可以从 Logo 中提炼两类微交互：

- 花瓣能量：用于成功、完成、推荐问题的轻量展开或亮起。
- 充电斜线：用于发送、运行、入库进度、Trace 链路流动。

这些符号只能作为细节增强，不应成为页面背景主装饰。

## 8. 前端落地标准

### 8.1 主题收敛

当前前端存在 `index.css`、`admin.css`、SCSS 模块、Tailwind 配置、Ant Design token 等多套样式入口。后续 UI 升级应先统一变量，再逐步迁移页面。

建议顺序：

1. 在全局 CSS 中建立品牌 Token，保留旧变量兼容映射。
2. 将 Ant Design `colorPrimary` 从当前蓝色调整为深能源绿。
3. 将 Tailwind 的 `primary`、`ring`、`chat-user` 等变量映射到品牌体系。
4. 管理端 `.admin-layout` 的 indigo、purple、cyan 装饰逐步替换为绿色、青色和墨蓝。
5. 页面级 SCSS 中的硬编码蓝色逐步替换为语义变量。

迁移检查表：

| 层级 | 检查对象 | 完成标准 |
| --- | --- | --- |
| 主题入口 | `App.tsx` / Ant Design `ConfigProvider` | `colorPrimary`、链接色、焦点色与品牌绿一致，信息色映射到深青。 |
| 全局 CSS | `index.css`、`admin.css` | 新品牌 token 位于入口层；旧蓝色变量只作为兼容别名，不再作为命名源。 |
| Tailwind | `tailwind.config.js` 与 CSS HSL 变量 | `primary`、`ring`、`chat-user`、阴影 glow 迁移到品牌语义或删除装饰用途。 |
| 基础组件 | `components/ui/*`、AntD 包装组件 | `default`、`outline`、`ghost`、`destructive` 语义统一，按钮不再默认使用紫蓝渐变。 |
| 管理端页面 | `pages/admin/**` | `indigo`、`purple`、`blue` 的业务含义被重新归类为主色、信息、链接或文件类型色。 |
| Chat 与用户端 | `pages/chat/**`、`components/sender/**` | 发送使用橙色高意图，引用和知识库上下文使用绿色，运行中使用青色。 |
| 图表 | `components/admin/*Chart*` | `primary` 序列为能源绿，链路/耗时可用青色，异常统一语义红。 |

### 8.2 组件统一验收

每个基础组件升级完成后，需要满足：

| 组件 | 必须覆盖的状态 | 额外验收 |
| --- | --- | --- |
| Button | default、hover、active、focus、disabled、loading | 主操作区最多一个强按钮；图标按钮有 tooltip 或 `aria-label`；触屏热区不小于 44px。 |
| Input / Select / Textarea | default、hover、focus、invalid、disabled、readonly、loading | label 可见；错误在字段下方；Chat 输入区有最大高度和内部滚动。 |
| Table / List | loading、empty、error、hover、selected、sorted、pagination | 状态列用颜色点 + 文案；关键 ID 可复制；小屏有明确横向滚动或列降级策略。 |
| Badge / Tag / Status | default、success、running、pending、failed、disabled | 不只用颜色表达；浅底文字对比度达标；状态语义跨页面一致。 |
| Card / Panel | default、hover、selected、focused、empty | 不做卡片套卡片；浮层阴影和普通容器边框有明确层级差异。 |
| Dialog / Drawer | opening、open、closing、error、unsaved | 有关闭入口、Esc 支持和焦点管理；遮罩足以隔离背景但不制造重压迫。 |
| Toast / Message | success、info、warning、error、loading | 2 到 5 秒自动消失；不抢焦点；错误提示包含下一步动作。 |
| Chart | loading、empty、error、interactive、reduced-motion | 有图例、单位、tooltip、表格替代或摘要；不靠颜色单独表达数据含义。 |

### 8.3 页面验收

每个页面升级完成后，需要检查：

- 是否能在首屏识别品牌主色和产品气质。
- 是否只有一个最重要的强操作。
- 是否保留工作台信息密度，没有退化为营销式布局。
- 状态色是否符合成功、运行、等待、失败语义。
- 表格与详情是否保留关键 ID 的复制能力。
- Chat 页输入区是否稳定固定，引用是否清楚可点。
- 是否在 375px、768px、1024px、1440px 四类宽度下没有非预期遮挡、溢出和操作区混乱。
- 是否支持键盘 Tab 顺序、焦点可见、弹窗焦点回收和图标按钮可读标签。
- 是否在 `prefers-reduced-motion` 下关闭非必要动画，且运行中、成功、失败状态仍清楚。
- 是否完成普通文字 4.5:1、图标/大字 3:1 的核心对比检查。

## 9. 不建议方向

- 不继续把蓝紫或靛蓝作为全局主品牌色。
- 不使用大面积渐变、霓虹光效、装饰性光球或复杂背景。
- 不把橙色用作所有按钮颜色，它只服务高意图动作。
- 不把黄色作为主按钮或正文强调色。
- 不在管理端使用营销首页式大 Hero。
- 不通过卡片套卡片制造层级，优先用标题、分割线、间距和表格结构表达层级。

## 10. 总结

本项目的 UI 应围绕公司 Logo 建立“绿色可信、橙色高效、青色链路、墨蓝专业”的完整视觉体系。用户端保持明亮、轻盈、可阅读，帮助普通用户完成连续问答与引用核验；管理端保持高密度、可扫描、可追溯，帮助管理员快速定位知识库、入库任务、Prompt、模型和 Trace 链路问题。

后续所有页面和组件的视觉升级，都应先对齐本文档的品牌 Token、布局节奏、组件状态与交互反馈，再进入具体实现。
